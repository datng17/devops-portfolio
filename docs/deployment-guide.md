# Deployment guide

How to build the eks-portfolio stack from an empty AWS account, verify it,
prove it is resilient, what it costs, and how to shut it down again.

- Region `us-east-1`, cluster `eks-portfolio`, namespace `portfolio`, site
  `https://test.name.vn` (DNS hosted outside AWS, records added by hand).
- Terraform roots: `terraform/bootstrap` (state bucket, local state),
  `terraform/infra` (VPC, endpoints, ECR, EKS, IAM, IRSA), `terraform/platform`
  (AWS Load Balancer Controller). Then `k8s/platform` and `k8s/app` with
  kustomize, then Jenkins.
- Commands are PowerShell 7 on Windows unless marked bash. Run the `*.sh`
  scripts with Git Bash (`& "C:\Program Files\Git\bin\bash.exe" scripts/...`);
  plain `bash` on this machine resolves to WSL, which has no distro.

## 1. Prerequisites

| Tool | Check | Notes |
|---|---|---|
| AWS CLI v2 | `aws --version` shows `aws-cli/2.x` | v1 must not come first on PATH: `aws eks get-token` (kubectl and the helm provider) needs v2 |
| Terraform >= 1.10 | `terraform version` | S3 backend with native lockfile (`use_lockfile = true`), no DynamoDB |
| kubectl 1.36-1.38 | `kubectl version --client` | Cluster runs 1.37 |
| Docker Desktop | `docker version` | BuildKit (the Dockerfile uses cache mounts); also runs Jenkins |
| Git for Windows | `& "C:\Program Files\Git\bin\bash.exe" --version` | Runs the bash scripts |
| PowerShell 7 | `$PSVersionTable.PSVersion` | `scripts/*.ps1` need `#Requires -Version 7` |
| Node 22 (optional) | `node -v` | Only for running lint/tests outside Docker/Jenkins |

You also need:

- An IAM identity with admin rights (`aws sts get-caller-identity`). It gets
  the EKS cluster-admin access entry unless `admin_principal_arn` is set.
- Your public IP for `admin_cidrs` (the EKS public endpoint allows nothing
  else): `(Invoke-RestMethod https://checkip.amazonaws.com).Trim()`. Local
  Jenkins egresses from the same IP. If your IP changes, kubectl and the
  platform providers time out (`dial tcp ...:443: i/o timeout`) until you
  update `admin_cidrs` and apply `terraform/infra` again.
- Access to the DNS zone of `test.name.vn` (Cloudflare here). Records must be
  "DNS only", not proxied.

Gitignored local files (never commit them): `terraform/*/backend.hcl`,
`terraform/*/terraform.tfvars`, `terraform/bootstrap/terraform.tfstate`,
`k8s/**/*.env`, `jenkins/secrets/`. Each has a committed `.example`, except
the ones generated by Terraform or scripts.

## 2. Deploy, in order

### 2.1 State bucket (bootstrap)

```powershell
terraform -chdir=terraform/bootstrap init
terraform -chdir=terraform/bootstrap apply
terraform -chdir=terraform/bootstrap output -raw state_bucket_name   # eks-portfolio-tfstate-<account_id>-us-east-1
```

The bucket has versioning, SSE (AES256 + bucket key), a public access block,
BucketOwnerEnforced, a TLS-only policy, 90-day expiry of noncurrent versions
and `prevent_destroy`. Its own state stays local in
`terraform/bootstrap/terraform.tfstate`; keep that file.

### 2.2 ACM certificate (two phases, outside Terraform)

The certificate is requested and validated outside Terraform; `terraform/infra`
only looks it up (`data "aws_acm_certificate"`, status ISSUED). So
`terraform destroy` never deletes it and a rebuild needs no new DNS
validation. (The first build managed it in Terraform with an
`acm_wait_for_validation` switch; it was moved out for this reason.)

Phase 1, request and publish the validation record:

```powershell
$certArn = aws acm request-certificate --region us-east-1 --domain-name test.name.vn `
  --validation-method DNS --key-algorithm RSA_2048 --query CertificateArn --output text
aws acm describe-certificate --region us-east-1 --certificate-arn $certArn `
  --query "Certificate.DomainValidationOptions[0].ResourceRecord" --output table
```

Add that CNAME at the DNS provider (DNS only). Keep it there for good:
ACM uses it for automatic renewal.

Phase 2, wait for ISSUED before the infra plan (the data source fails
otherwise):

```powershell
aws acm wait certificate-validated --region us-east-1 --certificate-arn $certArn
aws acm describe-certificate --region us-east-1 --certificate-arn $certArn --query Certificate.Status --output text   # ISSUED
```

Skip this section on a rebuild if the certificate still exists.

### 2.3 Infra (VPC, endpoints, ECR, EKS, IAM, IRSA)

```powershell
Copy-Item terraform/infra/backend.hcl.example terraform/infra/backend.hcl             # set bucket
Copy-Item terraform/infra/terraform.tfvars.example terraform/infra/terraform.tfvars   # set admin_cidrs = ["<your ip>/32"]
terraform -chdir=terraform/infra init "-backend-config=backend.hcl"
terraform -chdir=terraform/infra plan -out=tfplan
terraform -chdir=terraform/infra apply tfplan
```

Quote `"-backend-config=backend.hcl"` in PowerShell; unquoted it fails with
"No positional arguments are expected". With `-chdir`, the path is relative
to the root directory.

About 88 resources, 15-20 minutes (the EKS control plane is most of it):
VPC 10.0.0.0/16 with public /24s and private /20s in us-east-1a/1b and one
NAT Gateway; S3 gateway endpoint plus interface endpoints for
`interface_endpoint_services` (`ecr.api`, `ecr.dkr`, `logs`); ALB, node and
endpoint security groups; ECR repo `portfolio` (IMMUTABLE tags, keep last 20,
`force_delete = true` in `ecr.tf`); EKS `eks-portfolio` 1.37 (API auth mode,
public endpoint limited to `admin_cidrs`, private endpoint on, KMS secrets
encryption, api/audit/authenticator logs kept 7 days); node group `default`
(2x t3.medium AL2023, gp3 20 GB, IMDSv2 hop limit 1); add-ons vpc-cni,
kube-proxy, coredns, aws-ebs-csi-driver, metrics-server; IRSA roles
`eks-portfolio-dev-{ebs-csi,lbc,log-sink}`; log group
`/eks/eks-portfolio/portfolio-nginx`; IAM user `jenkins-ci` and role
`jenkins-deployer`.

```powershell
aws eks update-kubeconfig --region us-east-1 --name eks-portfolio   # = terraform output -raw kubeconfig_command
kubectl get nodes -o wide
```

Push the first image. The manifests start on tag `local`, and IMMUTABLE tags
mean it can be pushed once per repository:

```powershell
$repo = terraform -chdir=terraform/infra output -raw ecr_repository_url
aws ecr get-login-password --region us-east-1 | docker login --username AWS --password-stdin ($repo -split '/')[0]
docker build -t portfolio:local .
docker tag portfolio:local "${repo}:local"
docker push "${repo}:local"
```

### 2.4 Platform (AWS Load Balancer Controller)

```powershell
Copy-Item terraform/platform/backend.hcl.example terraform/platform/backend.hcl   # same bucket, key platform/terraform.tfstate
terraform -chdir=terraform/platform init "-backend-config=backend.hcl"
terraform -chdir=terraform/platform plan -out=tfplan
terraform -chdir=terraform/platform apply tfplan
```

Reads the infra outputs through `terraform_remote_state` and installs the
`aws-load-balancer-controller` chart 3.6.0 in kube-system (2 replicas, PDB,
IRSA role `eks-portfolio-dev-lbc`). It also writes the gitignored
`k8s/platform/log-sink-config.env`. The providers exec `aws eks get-token`;
set `aws_cli_command` to the v2 exe if v1 is first on PATH.

### 2.5 k8s/platform (namespace, StorageClass, log-sink)

```powershell
kubectl apply -f k8s/platform/namespace.yaml           # the server dry-run needs the namespace to exist
kubectl apply --dry-run=server -k k8s/platform
kubectl apply -k k8s/platform
kubectl -n portfolio rollout status statefulset/log-sink --timeout=5m
kubectl -n portfolio get pvc,pods -o wide
```

Namespace `portfolio` (PSA restricted, ALB readiness-gate injection),
StorageClass `gp3` (encrypted, WaitForFirstConsumer, reclaimPolicy
**Retain**), and the one-replica Fluent Bit `log-sink` StatefulSet with a 5Gi
PVC. Apply it before the app: Nginx resolves the `log-sink` Service once at
startup.

### 2.6 First app deploy and DNS

```powershell
pwsh scripts/render-k8s-config.ps1            # writes k8s/app/ingress-config.env (cert ARN, ALB SG, ECR URL)
kubectl apply --dry-run=server -k k8s/app
kubectl apply -k k8s/app
kubectl -n portfolio rollout status deployment/portfolio --timeout=5m
kubectl -n portfolio get ingress portfolio -o jsonpath='{.status.loadBalancer.ingress[0].hostname}'
```

Point `test.name.vn` at that hostname with a CNAME (DNS only). The ALB
hostname changes on every rebuild, so update the record each time.

The LBC only injects the ALB readiness gate into pods created after the
TargetGroupBinding exists. On a fresh cluster, restart once so the first pods
get it:

```powershell
kubectl -n portfolio rollout restart deployment/portfolio
kubectl -n portfolio get pods -o wide        # READINESS GATES 1/1, one pod per AZ
```

### 2.7 Jenkins

```powershell
pwsh scripts/render-jenkins-secrets.ps1 -CreateAccessKey    # creates the jenkins-ci access key, writes jenkins/secrets/*
docker compose -f jenkins/docker-compose.yml up -d --build
```

Open http://localhost:8080 (bound to loopback only), user `admin`, password
in `jenkins/secrets/jenkins_admin_password`. JCasC creates the `portfolio`
job, which polls `main` every 2 minutes. Stages: Checkout, Install, Lint &
Test, Build Image, Push (skipped if the tag exists), Deploy, Verify Rollout
(automatic `rollout undo` on failure), Smoke Test. The build runs as
`jenkins-deployer` (assumed from the `jenkins-ci` key), which can push to the
ECR repo and has Edit in namespace `portfolio` only.

Rollback drill: "Build with Parameters" with `OVERRIDE_IMAGE_TAG=doesnotexist`.
The new pod hits ImagePullBackOff, the 120 s progress deadline expires,
`verify-rollout.sh` undoes the rollout and the build goes red while the site
keeps serving.

The access key is deliberately outside Terraform state. `scripts/teardown.sh`
deletes it before `terraform destroy`, which would otherwise fail on the IAM
user.

```powershell
}                                            # all ACTIVE
kubectl top nodes
kubectl -n kube-system get deploy aws-load-balancer-controller   # 2/2

# Workloads
kubectl -n portfolio get deploy,sts,hpa,pdb,pvc,ingress
kubectl -n portfolio get pods -o wide        # portfolio pods spread over both AZs, READINESS GATES 1/1

# Edge
& "C:\Program Files\Git\bin\bash.exe" scripts/smoke-test.sh https://test.name.vn   # 4/4 checks
curl.exe -sI http://test.name.vn | Select-Object -First 2                          # 301 to https
curl.exe -s https://test.name.vn/healthz                                           # ok

# Logs (Nginx -> syslog UDP 5140 -> log-sink -> PVC + CloudWatch)
aws logs tail /eks/eks-portfolio/portfolio-nginx --since 5m
```

Known quirks:

- `nginx-logging` ConfigMap has no hash suffix; after changing it run
  `kubectl -n portfolio rollout restart deployment/portfolio`.
- Zone spread is preferred, not required, so a rollout can leave both pods in
  one AZ. The next rollout usually re-spreads them.
- `log-sink` is distroless; to read `/data`, start a temporary pod on the
  same node that mounts the PVC read-only.

## 4. Resilience and HPA drills

These drills show that the `portfolio` Deployment autoscales and stays up
through pod loss, the loss of one AZ's node, and rolling updates. Run them
against the live cluster (`eks-portfolio`, namespace `portfolio`). Captured
results are in `README.md` ("Resilience evidence") and `docs/evidence/`.

On Windows, run the shell scripts with Git Bash
(`"C:\Program Files\Git\bin\bash.exe" scripts/...`); plain `bash` may resolve
to WSL.

### What makes it work

- 2 replicas minimum, spread across us-east-1a and us-east-1b (zone
  anti-affinity + topology spread).
- `maxSurge: 1`, `maxUnavailable: 0`: a rollout never drops below the current
  capacity.
- PDB `minAvailable: 1`: a drain can evict only one portfolio pod at a time.
- `preStop` sleep 30 s + 45 s grace: a terminating pod keeps serving while the
  ALB deregisters it and endpoints update. It was 10 s at first; Drill 3 then
  lost 3 requests because the drain also evicted the AWS Load Balancer
  Controller leader and the standby needed about 20 s to take the lease and
  deregister the target.
- ALB readiness gates (`elbv2.k8s.aws/pod-readiness-gate-inject`): a new pod
  only counts as Ready once the ALB reports its target healthy, so a rollout
  can't outrun the ALB.
- HPA (2-5, CPU 60%, memory 75%) measures against the requests (50m CPU,
  64Mi). Static nginx uses almost no CPU, so the load test has to be
  aggressive. The 120 s scale-down stabilization window stops flapping.

### Availability probe (curl loop)

Every drill runs this in a second terminal and is judged on its output:

```bash
scripts/availability-probe.sh https://test.name.vn/ 0   # Ctrl-C to stop
```

It sends one request per loop (fresh connection each time, `INTERVAL=0.2`,
5 s timeout) and prints the count per status code. `000` means no HTTP
response. Pass = `non-200: 0`. Give it a fixed duration instead of `0` to stop
on its own. The rate is bounded by round-trip latency to us-east-1 (about
1 request/s from Vietnam); run two copies for more samples.

The bare-curl equivalent:

```bash
while true; do curl -s -o /dev/null -w '%{http_code}\n' --max-time 5 https://test.name.vn/; sleep 0.2; done | sort | uniq -c
```

### Drill 1: HPA scale-out and scale-in

```bash
scripts/hpa-load-test.sh
```

Applies `k8s/tests/k6-load.yaml` (pinned `grafana/k6` Job, about 5 minutes,
up to 40 VUs with no think time, no connection reuse so new replicas get
traffic), prints `current/desired/ready` replicas, CPU/memory utilization and
pods per node every 15 s, prints the k6 summary, waits for the HPA to return
to 2, and deletes the Job and ConfigMap (also on Ctrl-C).

Expected: 2 → 5 within about a minute of load, back to 2 about 2-3 minutes
after the load stops (120 s window plus metrics lag), k6 thresholds pass
(`http_req_failed < 1%`). 5 replicas need 250m CPU of requests, which fits on
the 2 existing t3.medium nodes; there is no cluster autoscaler.

### Drill 2: delete a pod

```bash
scripts/availability-probe.sh https://test.name.vn/ 0 &   # or second terminal
kubectl -n portfolio get pods -l app.kubernetes.io/name=portfolio -o wide
kubectl -n portfolio delete pod <one portfolio pod>
kubectl -n portfolio get pods -l app.kubernetes.io/name=portfolio -o wide -w   # until the replacement shows READINESS GATES 1/1 and 1/1 Ready
# stop the probe
```

Expected: `non-200: 0`. The other pod serves while the deleted one runs its
preStop sleep and the ReplicaSet brings up a replacement.

### Drill 3: lose one AZ (cordon + drain a node)

Drain the us-east-1b node. The us-east-1a node holds `log-sink-0`, whose gp3
volume is zonal, so draining 1a would leave log-sink Pending until uncordon
(serving would be fine, nginx syslog would drop).

```bash
scripts/availability-probe.sh https://test.name.vn/ 0 &
NODE=$(kubectl get nodes -l topology.kubernetes.io/zone=us-east-1b -o name)
kubectl cordon "$NODE"
kubectl drain "$NODE" --ignore-daemonsets --delete-emptydir-data --timeout=5m
kubectl -n portfolio get pods -o wide        # both portfolio pods now in 1a
# keep the probe running a minute in the degraded state, then:
kubectl uncordon "$NODE"
# stop the probe
```

Expected: `non-200: 0`. The PDB lets the drain evict one portfolio pod; it is
recreated in us-east-1a while the existing 1a pod serves. If the LBC leader
runs on the drained node, ALB deregistration waits for leader failover (about
20 s), which is why the preStop sleep is 30 s. kube-system
deployments (LBC, CoreDNS, metrics-server, EBS CSI) run 2 replicas with
`maxUnavailable: 1` PDBs. After uncordon nothing moves back on its own; the
rollout in Drill 4 re-spreads the pods across both AZs.

### Drill 4: rolling update under load

Run the load Job and the probe, and roll the Deployment while the HPA is at 5:

```bash
scripts/hpa-load-test.sh &                       # wait until current=5
scripts/availability-probe.sh https://test.name.vn/ 0 &
kubectl -n portfolio rollout restart deployment/portfolio
kubectl -n portfolio rollout status deployment/portfolio --timeout=10m
# stop the probe after the rollout; let hpa-load-test.sh finish
```

A Jenkins deploy (push to `main`) is the same kind of rollout with a new
image; run the probe across a pipeline run to measure it.

Expected: `non-200: 0`, k6 `http_req_failed` stays under 1%.

### Drill cleanup

`hpa-load-test.sh` deletes the Job/ConfigMap itself. If it was killed hard:

```bash
kubectl delete -f k8s/tests/k6-load.yaml --ignore-not-found
kubectl get nodes        # no SchedulingDisabled
```

The endpoint line follows `interface_endpoint_services` in
`terraform/infra/variables.tf`: each service is one endpoint with an ENI in
both private subnets, so it costs 2 × $7.30 = $14.60/month. Adding `sts`
would add $14.60. Turning them off saves $43.80/month and is a targeted
change (it destroys only the 3 interface endpoints; ECR and CloudWatch
traffic then goes through the NAT Gateway):

```powershell
terraform -chdir=terraform/infra plan -var enable_interface_endpoints=false   # 3 to destroy
```

Break-even for the interface endpoints. They cost $43.80/month fixed and save
$0.045 - $0.01 = $0.035 per GB that would otherwise go through the NAT
Gateway. $43.80 / $0.035 = about **1,251 GB/month**. This workload moves a
few GB a month at most, and ECR image layers come from S3 through the free
gateway endpoint anyway. At this scale the endpoints are a security choice
(AWS API traffic stays on private IPs) and not a cost saving.

Break-even for running on demand. Always on is ~$249/month. Torn down
between demos, the stack costs ~$0.34 per hour it exists, plus about 40
minutes to rebuild (sections 2.3-2.6) and a DNS update. Ten 4-hour demo
sessions a month come to about $14. What stays after teardown costs nothing
meaningful: the state bucket holds a few MB (well under $0.01/month), the
ACM certificate is free, and a KMS key pending deletion isn't billed.

## 6. Teardown

```powershell
& "C:\Program Files\Git\bin\bash.exe" scripts/teardown.sh           # prints the plan and cost, asks for the cluster name
& "C:\Program Files\Git\bin\bash.exe" scripts/teardown.sh --check   # read-only leftover check, changes nothing
```

`--yes` skips every prompt (including Terraform's). Before it changes
anything, the script checks the tools, the AWS identity, that both Terraform
roots are initialised, and that the EKS API is reachable. If your IP has left
`admin_cidrs`, it stops and prints the fix.

What it does, in order:

1. Stops the local Jenkins container, so a polled build can't recreate the
   Ingress halfway through.
2. Deletes all Ingresses (and any LoadBalancer Services), waits until the
   controller has deleted the ALB (`aws elbv2 wait load-balancers-deleted`),
   then waits for the ALB ENIs to leave the VPC.
3. Deletes namespace `portfolio` (app, HPA, PDB, log-sink StatefulSet, PVC),
   StorageClass `gp3` and the Released PVs.
4. Deletes the EBS volumes behind those PVs. `gp3` is `reclaimPolicy: Retain`,
   so nothing else would delete them. Volumes are found from the PV volume
   handles and from the CSI tags (`kubernetes.io/cluster/eks-portfolio` +
   `kubernetes.io/created-for/pvc/name`); node root volumes are never touched.
5. Deletes all access keys of `jenkins-ci`. They were created outside
   Terraform, and IAM refuses to delete a user that still has keys.
6. `terraform destroy` in `terraform/platform` (LBC Helm release, generated
   env file).
7. `terraform destroy` in `terraform/infra` (about 88 resources, 10-15
   minutes). ECR is deleted with its images (`force_delete = true`). The EKS
   KMS key is only scheduled for deletion (30-day window, not billed while
   pending). If EKS recreated `/aws/eks/eks-portfolio/cluster` after Terraform
   deleted it, the script deletes it again.
8. Leftover check, also available on its own with `--check`.

Kept on purpose: the state bucket (`prevent_destroy`), the ACM certificate
(Terraform only reads it) and the DNS records. The CNAME to the old ALB then
points nowhere until the next deploy.

Acceptance test (also part of `--check`): nothing tagged for the cluster
remains.

```powershell
aws resourcegroupstaggingapi get-resources --resource-type-filters elasticloadbalancing:loadbalancer `
  --tag-filters Key=elbv2.k8s.aws/cluster,Values=eks-portfolio --query "ResourceTagMappingList[].ResourceARN"
aws ec2 describe-network-interfaces --filters Name=tag:cluster.k8s.amazonaws.com/name,Values=eks-portfolio --query "NetworkInterfaces[].NetworkInterfaceId"
aws ec2 describe-volumes --filters Name=tag-key,Values=kubernetes.io/cluster/eks-portfolio --query "Volumes[].VolumeId"
aws kms list-aliases --query "Aliases[?AliasName=='alias/eks/eks-portfolio']"
aws logs describe-log-groups --log-group-name-prefix /aws/eks/eks-portfolio
```

All should return empty lists. The tagging API can list a deleted load
balancer for a while; `--check` confirms each ARN with
`aws elbv2 describe-load-balancers`. The KMS key no longer has an alias but
shows `KeyState: PendingDeletion` in `aws kms describe-key`.

To rebuild later, start at section 2.3 (the bucket and the certificate are
still there), then update the DNS CNAME to the new ALB hostname and run
`pwsh scripts/render-jenkins-secrets.ps1 -CreateAccessKey` for a new Jenkins
key.

### Removing the state bucket (manual, only when you're done for good)

`teardown.sh` never does this. Run it only after both destroys succeeded,
since the bucket holds their state.

1. Remove the `lifecycle { prevent_destroy = true }` block from
   `aws_s3_bucket.state` in `terraform/bootstrap/main.tf` (local edit, don't
   commit it).
2. Empty every object version and delete marker. The bucket is versioned, so
   `aws s3 rm --recursive` would only add delete markers:

   ```powershell
   $b = terraform -chdir=terraform/bootstrap output -raw state_bucket_name
   foreach ($kind in 'Versions', 'DeleteMarkers') {
     $json = aws s3api list-object-versions --bucket $b --max-items 1000 --output json `
       --query "{Objects: $kind[].{Key: Key, VersionId: VersionId}}"
     if (($json | ConvertFrom-Json).Objects) {
       $json | Set-Content -Encoding utf8NoBOM delete.json
       aws s3api delete-objects --bucket $b --delete file://delete.json
       Remove-Item delete.json
     }
   }
   $v = aws s3api list-object-versions --bucket $b --output json | ConvertFrom-Json
   (($v.Versions | Measure-Object).Count) + (($v.DeleteMarkers | Measure-Object).Count)   # 0; repeat the loop if not
   ```

3. Destroy the bootstrap root and restore the file:

   ```powershell
   terraform -chdir=terraform/bootstrap destroy
   git checkout -- terraform/bootstrap/main.tf
   ```

Alternative to step 2: set `force_destroy = true` on the bucket, apply, then
destroy; Terraform then deletes all versions itself.

If you also want the certificate gone:
`aws acm delete-certificate --region us-east-1 --certificate-arn <arn>`
(only once no ALB uses it), then remove the validation CNAME.

## 7. Interview talking points

- Controller-created resources (the ALB from the Ingress, the EBS volume from
  the PVC) live outside Terraform state. Delete them first, or
  `terraform destroy` gets stuck on VPC dependencies. The Retain
  StorageClass means the volume has to be deleted explicitly.
- FinOps in practice: ~$0.34/h only while demoing instead of ~$249/month,
  with one script to tear down and a measured rebuild. The interface
  endpoints only pay for themselves above ~1,251 GB/month; here they're a
  security decision, and the toggle is one variable.
- One NAT Gateway for two AZs: $32.85/month saved against an AZ-a egress
  single point of failure. AWS API traffic avoids NAT through the endpoints.
- Least privilege end to end: IRSA roles pinned to one ServiceAccount
  (`sub`) and audience (`aud`), IMDSv2 with hop limit 1 so pods can't use
  the node role, EKS access entries instead of `aws-auth`, and Jenkins as a
  user that can only assume a role with ECR push and Edit in one namespace.
- Security group chain: Terraform owns the ALB SG, the controller is told not
  to manage backend rules, and nodes accept 8080 only from the ALB SG.
- Immutable ECR tags plus git-SHA images make rollbacks deterministic. The
  pipeline rolls back on its own: progress deadline 120 s, then
  `rollout undo` (build #5, `OVERRIDE_IMAGE_TAG=doesnotexist`).
- Zero-downtime is measured, not assumed: ALB readiness gates, maxUnavailable
  0, PDB, and a preStop sleep raised from 10 s to 30 s after a drain drill
  lost 3 requests during an LBC leader failover.
- HPA scales on requests, so right-sized requests matter. Zone anti-affinity
  is preferred, not required: with 2 AZs a required rule would leave replicas
  3-5 Pending.
- EBS is zonal and ReadWriteOnce, so the stateful part (log-sink) is a
  one-replica StatefulSet, kept out of the HPA tier.
- The ACM certificate is outside Terraform, so a rebuild needs no new DNS
  validation. The state bucket has `prevent_destroy` and S3-native locking
  (`use_lockfile`), no DynamoDB table.
- Known trade-off: mounting the Docker socket into Jenkins is root on the
  host. Acceptable for a loopback-only demo; in production use Kaniko,
  rootless BuildKit or ephemeral agents.
